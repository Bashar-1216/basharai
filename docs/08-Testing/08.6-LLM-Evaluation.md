## 1. AI Quality Evaluation Overview

على عكس مشاريع الويب التقليدية التي تنتهي جودتها باجتياز اختبارات الكود، يتطلب العمل مع النماذج اللغوية الضخمة (LLMs) مساراً مستقلاً تماماً للتحقق من خلو الردود من الهلوسة ودقة البيانات المسترجعة دلالياً. 

نقوم بتصميم خطة **تقييم الذكاء الاصطناعي (LLM Evaluation)** لزرع حلقة مراقبة جودة مستمرة تثبت للجان التوظيف التقنية تمكن المرشح الكامل من أدوات الملاحظة (Observability).

---

## 2. The RAG Triad Framework

نعتمد إطار عمل **ثلاثي RAG (RAG Triad)** المعتمد علمياً لقياس جودة النظام المتكامل بالكامل:

```
                  [User Query]
                     /      \
       (3) Answer   /        \    (1) Context
       Relevance   /          \    Relevance
                  v            v
           [Generated Response] <─── [Retrieved Context]
                            (2) Groundedness
```

1. **Context Relevance (ملائمة السياق):** يقيس مدى ارتباط الفقرات المسترجعة من pgvector بالسؤال الفعلي للزائر (هل قمنا بجلب مستندات مفيدة أم عشوائية؟).
2. **Groundedness / Faithfulness (الموثوقية):** يقيس مدى التزام الرد بالفقرات المسترجعة (هل قام النموذج بتأليف معلومات غير موجودة في السيرة الذاتية - هلوسة؟).
3. **Answer Relevance (ملائمة الإجابة):** يقيس مدى إجابة الرد المولد على سؤال المستخدم بشكل مباشر ودقيق ودون دوران خارج السياق.

## 3. Evaluation Metrics & Scoring Targets | عتبات القبول

تتراوح درجات التقييم رياضياً بين **0.0 (الأسوأ) و 1.0 (الأكمل)**. نحدد الأهداف التالية كحدود دنيا لقبول التحديثات في بيئة الإنتاج:

| Metric Name | Mathematical Concept | Minimum Target | Action on Failure |
|-------------|-----------------------|----------------|-------------------|
| **Context Relevance** | cosine similarity / LLM scoring | **>= 0.85** | Adjust chunk size or search k |
| **Groundedness** | overlap NLI (Natural Lang. Inference) | **>= 0.90** | Tighten system instructions |
| **Answer Relevance**| semantic correlation to query | **>= 0.88** | Adjust prompt examples / temperature |

## 4. Golden Test Set (The Golden 25 Queries)

نحتفظ بملف محمي يحتوي على **25 سؤالاً ذهبياً ثنائي اللغة** يغطي أدق التفاصيل الفنية وخبرات العمل السابقة لربط حلقة التقييم بها:

### أمثلة للأسئلة الذهبية (Sample Golden Queries):
1. `AR`: "ما هي إنجازات بشار في شركة جرامرلي؟"
   - *الإجابة المتوقعة:* عمل مهندس برمجيات وساهم في تطوير منصة الذكاء الاصطناعي وبنائها و...
2. `EN`: "Did Bashar sign an NDA for his work at Amazon?"
   - *Expected:* Yes, he complies with confidentiality requirements and case studies are NDA-safe.
3. `AR`: "هل يستطيع بشار بناء محرك بحث متجهي باستخدام pgvector؟"
   - *الإجابة المتوقعة:* نعم، يتقن استخدام pgvector وفهارس HNSW وتخزين التضمينات.

## 5. Automated Evaluation Runner (LLM-as-a-Judge)

نستخدم نموذج **GPT-4o-mini كحكم خارجي (LLM-as-a-Judge)** غير منحاز لتقييم جودة الردود المستخرجة آلياً:

- **آلية العمل:**
  1. يقوم خادم FastAPI بتشغيل الـ 25 سؤالاً ضد نموذج الـ RAG المطور محلياً.
  2. يسجل النظام: السؤال، والسياق المسترجع، والرد المولد.
  3. يرسل النظام حزمة البيانات للمدقق (GPT-4o-mini) مع موجه تدقيق صارم (Evaluation Prompt Template) يطلب منه تفنيد الرد وحساب الدرجات الثلاث وإرجاع النتيجة كـ JSON منظم.

```python
# Evaluator Prompt snippet
EVAL_SYSTEM_PROMPT = """
You are an expert technical QA judge. Evaluate the generated RAG response against the retrieved context.
Return a JSON payload with 'groundedness' (0.0 to 1.0) and a brief justification.
"""
```

## 6. Regression Testing & Prompt Protection

- **حماية الموجهات (Prompt Regression):**
  - عند قيام المطور بتحديث ملف الـ Prompt الرئيسي لـ RAG أو تعديل أي كود في FastAPI، يتم تفعيل أمر الفحص التلقائي لدفعة التقييم.
  - إذا تراجعت نسبة النجاح العامة (Pass rate) أو انخفض متوسط درجات الـ Groundedness عن العتبة المستهدفة، يتم رفض الدمج آلياً لحماية جودة الخدمة الحية.
