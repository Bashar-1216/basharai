## 1. Testing Philosophy

تركز استراتيجية الاختبارات في منصة bashar.ai على **بناء الثقة الهندسية الصارمة (Confidence-first Engineering)**. هدفنا هو التأكد من أن أي تعديل برمجي أو تحديث للـ Prompts لن يؤثر سلباً على تجربة المستخدم، ولا يتسبب في تراجع جودة الـ RAG (Prompt Regression)، ولا يزيد من زمن الكمون (Latency). 

تعتبر جودة الاختبارات بمثابة **أقوى دليل هندسي** يقدمه المرشح للجان التقييم، ليثبت أنه يبني أنظمة ذكاء اصطناعي حقيقية آمنة ومراقبة.

## 2. The Testing Pyramid & Coverage Targets

نقسم مستويات الاختبار لتطابق هرم الاختبارات المعياري لضمان السرعة والتكلفة الفعالة:

```
      /\
     /  \    End-to-End: UI Journeys, RTL Layout check (10% Coverage)
    / E2E\
   /------\  Integration: API Contracts, Database Queries (20% Coverage)
  / Integ. \
 /----------\ Unit Tests: UI logic, Text splitting, Utils (70% Coverage)
/    Unit    \
--------------
  [+] LLM Evaluation: Golden set validation (tracked separately - 90%+ pass rate)
```

### Coverage Goals Table:

| Test Level | Metric | Target Coverage | Speed Constraint |
|------------|--------|-----------------|------------------|
| **Unit Tests** | Statement / Branch | **>= 75%** | Ultra fast (< 5s run) |
| **Integration Tests** | Route / DB Queries | **>= 80%** | Medium (< 30s run) |
| **E2E Tests** | Critical paths only | **100% of core flows**| Slow (< 2min run) |
| **LLM Eval** | RAG Triad Metrics | **>= 90% Pass Rate** | Async background run |

## 3. Unified Testing Stack | مجموعة أدوات الاختبار المعتمدة

تم اختيار أدوات حديثة، خفيفة وسريعة تتوافق مع بيئة التطوير ثنائية اللغة:

| Focus Area | Tool Selected | Purpose & Integration |
|------------|---------------|-----------------------|
| **Frontend Unit/Integ** | **Vitest** | Fast React unit tests, native support for Next.js workspace configurations. |
| **Backend Unit/Integ** | **Pytest** | Async Python tests for FastAPI routers, mock patchers. |
| **E2E Testing** | **Playwright** | Multi-browser UI tests, explicit assertion for RTL direction. |
| **Load/Perf Testing** | **k6 (by Grafana)** | Lightweight JS scriptable loader to test API endpoints concurrency limits. |
| **LLM Quality Eval** | **DeepEval / Custom Judge**| Framework to compute context relevance and groundedness scores. |

## 4. CI/CD Integration Pipeline

تعمل كافة فئات الاختبارات (باستثناء اختبارات التحميل الثقيل k6) آلياً مع كل Pull Request في GitHub Actions:

```
GitHub Pull Request ──► Code lint check (Biome/Ruff)
                             │
                             ▼
Merge blocked ◄── Fail ── Unit & Integration Tests (Vitest/Pytest)
                             │
                             ▼
                         Pass ──► Deploy preview build to staging
                                     │
                                     ▼
                                 Run E2E UI Tests (Playwright) ──► Pass ──► Allow Merge
```

- يمنع دمج أي PR للمستودع الرئيسي إذا فشلت خطوة اختبارية واحدة لضمان ثبات بيئة الإنتاج دائمًا.

## 5. Strict Definition of Done (DoD)

لا تُعتبر أي مهمة برمجية مكتملة (Done) ومستعدة للإغلاق في لوحة المهام إلا بعد استيفاء الشروط التالية:
1. **خلوها من الأخطاء البصرية:** مطابقة كود التنسيق لـ Biome و Ruff بنسبة 100%.
2. **اجتياز الاختبارات الفردية:** كتابة اختبارات وحدة تغطي كافة السطور الجديدة ومسارات الخطأ المتوقعة.
3. **سلامة التكامل:** نجاح دمج الـ API وعمل قاعدة البيانات محلياً دون أخطاء.
4. **تأكيد السرية (NDA Check):** التحقق من خلو الكود تماماً من أي تسريب لمعلومات الشركات السابقة.
5. **موافقة حلقة التقييم:** استقرار مقاييس RAG للأسئلة المتأثرة فوق عتبة الـ 90%.
