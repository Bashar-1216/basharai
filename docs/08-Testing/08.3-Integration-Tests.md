## 2. Database Rollback Strategy for Transactional Isolation

لمنع حدوث تلوث في قاعدة البيانات المحلية (Database Pollution) وضمان عدم تأثر نتائج الاختبارات ببيانات الاختبارات السابقة:

- **استراتيجية التراجع التلقائي (Transactional Rollback):**
  - يتم تشغيل كل اختبار تكامل يتصل بقاعدة البيانات داخل **عملية مفرّقة (SQL Transaction)**.
  - عند انتهاء الاختبار (سواء نجح أو فشل)، نطلق أمر **`ROLLBACK`** للتراجع عن كافة عمليات الكتابة والتعديل والحذف التي تمت أثناء تشغيل الاختبار، مما يعيد قاعدة البيانات لحالتها النظيفة فوراً.
  - في اختبارات FastAPI، نستخدم الـ dependencies لتجهيز الـ Session وتجريده تلقائياً:
    ```python
    @pytest.fixture(scope="function")
    def db_session():
        transaction = connection.begin()
        session = Session(bind=connection)
        yield session
        session.close()
        transaction.rollback() # Auto rollback after test exit
    ```

## 3. Vector Indexing & Retrieval Integration (pgvector)

- **الهدف:** التأكد من صحة محاذاة وربط الفهارس المتجهية وعثور pgvector على الوثيقة المطلوبة دلالياً.
- **سيناريو الاختبار:**
  1. إدخال وثيقة تجريبية تحتوي على نص مميز (مثال: "Bashar worked on Grammarly AI platform team in San Francisco").
  2. توليد تضمين (Embedding) حقيقي أو محاكي لسؤال متعلق بالموضوع (مثال: "Where did Bashar work?").
  3. تنفيذ استعلام cosine similarity وتأكيد ظهور الوثيقة المدخلة في أعلى النتائج المسترجعة (Top-1).

## 4. Redis Cache Throttling Integration

- **الهدف:** التأكد من تفاعل FastAPI مع Redis بشكل متزامن وحفظ عدادات الـ Rate Limiting.
- **سيناريو الاختبار:**
  1. إرسال 5 طلبات متتالية من نفس هرم البصمة الرقمية (fingerprint ID) لـ `POST /api/v1/chat`.
  2. التحقق من إرجاع ردود ناجحة (HTTP 200) لأول 5 طلبات.
  3. التحقق من استقبال رد رفض (HTTP 429 Too Many Requests) في الطلب السادس وحفظ قيمة العداد في Redis بشكل مؤقت.
