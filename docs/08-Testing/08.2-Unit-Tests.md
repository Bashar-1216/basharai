## 1. Frontend Unit Testing (Vitest & React Testing Library)

تستهدف اختبارات وحدة الواجهة الأمامية التأكد من صحة سلوك المكونات الفردية وعمليات التبادل اللغوي دون الحاجة لبناء الخادم بالكامل.

### 1.1 فحص زر تبديل اللغة (Locale Switcher Test):
- **الهدف:** التأكد من أن النقر على زر التبديل يغير مسار اللغة (`ar`/`en`) ويحدّث ترويسة الاتجاه `dir` في وسم الـ HTML.
- **كود الفحص الافتراضي (Pseudocode):**
```typescript
import { render, screen, fireEvent } from "@testing-library/react";
import LocaleToggle from "@/components/LocaleToggle";

test("toggles language direction seamlessly", () => {
  render(<LocaleToggle currentLocale="en" />);
  const button = screen.getByRole("button", { name: /switch to arabic/i });
  fireEvent.click(button);
  expect(window.location.pathname).toContain("/ar");
});
```

### 1.2 فحص تصفية السيرة الذاتية (Resume Skill Filter Test):
- **الهدف:** التحقق من إخفاء المهارات غير المحددة وعرض المهارات الموافقة للتصنيف المختار (مثل تحديد "LLM/RAG" فقط).
- **حالة الاختبار:** تمرير مصفوفة مهارات تجريبية والتأكد من تطابق المخرج المرئي في المتصفح مع الفلتر المختار.

## 2. Backend Unit Testing (Pytest)

تستهدف اختبارات وحدة الخدمات الخلفية التحقق من صحة معالجة البيانات والتقطيع المتجهي وحساب مقاييس الأداء.

### 2.1 اختبار تجزئة النصوص وتراكبها (Recursive Text Splitter Test):
- **الهدف:** التأكد من التزام المقطع بالحد الأقصى لطول الكلمات وحساب التراكب (Overlap) الرياضي لضمان عدم ضياع الكلمات بين المقاطع المتجاورة.
- **كود الفحص الافتراضي (Pytest):**
```python
from app.services.rag_splitter import recursive_split

def test_recursive_split_bounds():
    sample_text = "This is a long engineering case study about RAG..."
    chunks = recursive_split(sample_text, chunk_size=100, chunk_overlap=20)
    
    for chunk in chunks:
        assert len(chunk) <= 100
        # Verify overlap contains preceding token context
```

### 2.2 اختبار استخلاص الميتاداتا (Metadata Extractor Test):
- **الهدف:** التأكد من فحص كود التدوينات واستخراج وسوم اللغة العربية/الإنجليزية والعناوين الرئيسية بشكل تلقائي لوضعها في فهارس pgvector.

## 3. Mocking Strategy & Token Conservation | استراتيجية المحاكاة وحفظ الميزانية

لمنع هدر ميزانية استهلاك الذكاء الاصطناعي (OpenAI API Tokens) ومنع إبطاء سرعة تشغيل الاختبارات اليومية:

- **عزل واجهات OpenAI (Mocking LLM Calls):**
  - نستخدم مكتبات محاكاة الطلبات (مثل `pytest-mock` أو `responses` في Python) لاعتراض أي استدعاء خارجي لمزودي الـ LLM (مثل `openai.chat.completions.create` أو `openai.embeddings.create`).
  - نقوم بإرجاع مخرجات نصية وهياكل متجهات ثابتة ومعدة مسبقاً (Mocked Response) دون الاتصال الحقيقي بالإنترنت أثناء اختبارات الوحدة.

```python
# Mocking OpenAI response example in Pytest

    mock_openai = mocker.patch("openai.resources.chat.Completions.create")
    mock_openai.return_value = {
        "choices": [{"message": {"content": "Mocked AI response for safety."}}]
    }
```
