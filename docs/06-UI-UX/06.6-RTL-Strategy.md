## 1. RTL Layout Architecture

يتطلب السوق الخليجي المستهدف **تجربة تعريب أصيلة من الدرجة الأولى (First-Class RTL)**. لا يكفي عكس العناصر برمجياً فحسب، بل يجب محاذاة كافة الجوانب البصرية والنصوص والهوامش بما يطابق تجربة القراءة والوعي الجغرافي العربي.

### الأساس المعماري:
- نستخدم وسم `dir="rtl"` على مستوى جذر الصفحة (`<html>`) للنسخة العربية.
- يتم إدارة تغيير الاتجاه تلقائياً في خادم Next.js بواسطة الـ Middleware بالتوازي مع تحميل ملف الترجمة المناسب.

## 2. Tailwind CSS Logical Properties | الخصائص المنطقية

لضمان نظافة الكود وعدم كتابة أسلوب تنسيق منفصل لكل لغة، يُمنع استخدام الخصائص الفيزيائية الصارمة ويُستبدل بها الخصائص المنطقية المعتمدة في Tailwind CSS 4:

```html
<!-- INCORRECT: Physical styling (requires manual RTL overrides) -->
<div class="mr-4 text-left">
  <!-- Breaks in Arabic unless you write: mr-4 rtl:mr-0 rtl:ml-4 -->
</div>

<!-- CORRECT: Logical styling (auto-adjusts on dir change) -->
<div class="me-4 text-start">
  <!-- me = margin-inline-end. Moves to left in LTR, and to right in RTL automatically -->
</div>
```

### مرجع استخدام الخصائص المنطقية:
- **Margins:** `ms-` (start) و `me-` (end) بدلاً من `ml-` و `mr-`.
- **Paddings:** `ps-` (start) و `pe-` (end) بدلاً من `pl-` و `pr-`.
- **Borders:** `border-s` و `border-e` بدلاً من `border-l` و `border-r`.
- **Alignments:** `text-start` و `text-end` بدلاً من `text-left` و `text-right`.

## 3. Mirrored vs. Non-Mirrored Elements

ليست كل عناصر واجهة المستخدم قابلة للعكس (Mirroring). توضح المصفوفة التالية كيفية التعامل مع العناصر البصرية المختلفة:

| Component Type | Action in RTL | Rationale |
|----------------|---------------|-----------|
| **Navigation Link Order** | **Mirrored** | Reading order flows right-to-left. |
| **Carousel Arrows** | **Mirrored** | Arrow direction follows progress direction (Right arrow moves backwards in RTL). |
| **Company Logos** | **Non-Mirrored** | Retain original trademark branding geometry. |
| **Code Blocks (`<pre>`, `<code>`)** | **Non-Mirrored (Always LTR)** | Code syntax is globally LTR (English basis). |
| **Observability Charts** | **Mixed** | Chart labels and text translated to Arabic, but time-series progression axis stays LTR (left to right) for technical clarity. |
| **Phone numbers / Dates** | **Non-Mirrored** | Read mathematically left-to-right. |

## 4. Arabic Typography Tuning | ضبط الخطوط والطباعة العربية

تختلف الحروف العربية بطبيعتها التشريحية عن الحروف اللاتينية. قمنا بضبط الأنماط التالية لخط `IBM Plex Sans Arabic` لضمان مقروئية فائقة:

1. **إلغاء التباعد بين الحروف (Disable Letter-spacing):**
   - في الخط الإنجليزي، نستخدم `tracking-tight` لضغط الأحرف.
   - **في الخط العربي:** يجب إيقاف التباعد تماماً (`tracking-normal` أو `tracking-[0]`) لأن الحروف العربية تتصل ببعضها، وأي تباعد بينها يشوه بنيتها الأساسية.
2. **زيادة ارتفاع الأسطر (Increase Line Height):**
   - تحتاج الكلمات العربية لارتفاع أسطر أكبر بنسبة **10% إلى 15%** مقارنة بالإنجليزية لمنع تداخل الحركات (الضمة، الفتحة، الكسرة) بين السطور المتجاورة:
     ```css
     /* Tailored Arabic typography adjustment override */
     :lang(ar) {
       line-height: 1.75;
     }
     ```

## 5. Bidirectional (BiDi) Text Handling

عند تداخل الكلمات الإنجليزية والتقنيات (مثل RAG, pgvector) داخل الجمل العربية:
- نستخدم رأس الـ CSS `unicode-bidi: plaintext` على المكونات التي تعرض نصوصاً برمجية أو رسائل مستخدمين مختلطة ليعالج المتصفح اتجاه الجمل وعلامات الترقيم تلقائياً.
- نغلف أي مصطلح تقني إنجليزي داخل جملة عربية بوسم `<bdi>` (Bi-directional Isolation) لمنع ارتداد علامات الترقيم (مثل النقاط والأقواس) إلى بداية الجملة بشكل خاطئ.

## 6. Form Fields & Inputs Alignment

- **محاذاة النصوص والرموز التعبيرية (Icons):**
  - تصطف تسميات الحقول (Labels) ومربعات النص (Inputs) في أقصى اليمين.
  - أيقونات الفحص والبحث (مثل عدسة البحث أو أيقونة قفل كلمة المرور) تنتقل تلقائياً لتستقر في أقصى اليسار داخل المربع لتسهيل حركة العين والمؤشر.
