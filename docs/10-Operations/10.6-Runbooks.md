## 1. Runbook 1 — Safe Production Database Migrations

يُستخدم هذا الدليل عند إجراء تعديلات على الجداول وتطبيقها في بيئة الإنتاج دون المساس ببيانات الزوار الحالية.

- **الخطورة:** 🔴 **مرتفعة** (تخريب البيانات).
- **خطوات التنفيذ:**
  1. صياغة التعديل محلياً وتحديث ملف `schema.prisma`.
  2. توليد ملف الهجرة البرمجية محلياً:
     ```bash
     pnpm prisma migrate dev --name add_new_fields
     ```
  3. التحقق من ملف الـ SQL الناتج وخلوه من أي أوامر هدم (`DROP COLUMN` أو `DROP TABLE`).
  4. تطبيق الهجرة في خادم الإنتاج السحابي (Railway DB) باستخدام الأمر الآمن:
     ```bash
     pnpm prisma migrate deploy
     ```
- **التحقق من النجاح:** تفحص لوحة Prisma Studio للتأكد من ظهور الحقول الجديدة واستقرار عمل خادم FastAPI.

## 2. Runbook 2 — Invalidation & Flushing of Redis Cache

يُستخدم عند رصد إجابات خاطئة مخزنة بالذاكرة المؤقتة أو بعد إجراء تحديثات طارئة على محتويات السيرة الذاتية.

- **الخطورة:** 🟢 **منخفضة** (زيادة مؤقتة في استهلاك توكنز OpenAI).
- **خطوات التنفيذ:**
  1. الاتصال بذاكرة Redis عبر الـ CLI الخاص بـ Railway:
     ```bash
     redis-cli -u $REDIS_URL
     ```
  2. لتفريغ كافة الردود المخزنة فقط دون التأثير على عدادات الـ Rate Limiting:
     ```redis
     KEYS response:chat:*
     # Delete identified keys dynamically
     ```
  3. لتفريغ كامل الذاكرة عند الحوادث الكبرى:
     ```redis
     FLUSHALL
     ```
- **التحقق من النجاح:** إجراء سؤال RAG جديد والتأكد من استدعاء OpenAI وحساب التكلفة في قاعدة البيانات مجدداً.

## 3. Runbook 3 — Re-Embedding Vector Store (Ingestion Run)

يُستخدم بعد تعديل ملفات دراسات الحالة MDX (أمازون/جرامرلي) لتوليد المتجهات الجديدة وتحديث قاعدة البيانات pgvector.

- **الخطورة:** 🟡 **متوسطة** (توقف مؤقت لاسترجاع RAG الصحيح).
- **خطوات التنفيذ:**
  1. دمج التحديثات في فرع `master` بنجاح.
  2. إرسال طلب للمنفذ المحمي (Admin Ingestion Endpoint) عبر لوحة التحكم أو سطر الأوامر:
     ```bash
     curl -X POST https://api.bashar.ai/api/v1/admin/ingest \
          -H "Authorization: Bearer <ADMIN_JWT_TOKEN>"
     ```
  3. يقرأ خادم FastAPI الملفات الجديدة، ويقطعها دلالياً، ويستدعي OpenAI Embeddings لتحديث قاعدة البيانات.
- **التحقق من النجاح:** مراجعة سجلات الحاوية على Railway والتأكد من ظهور رسالة: `"Ingestion completed. Embedded X new chunks successfully."`.

## 4. Runbook 4 — Hot-Fixing RAG Prompt Templates

يُستخدم لتعديل الموجهات البرمجية وأسلوب إجابة مساعد الذكاء الاصطناعي دون الحاجة لإعادة نشر كامل الحاوية.

- **الخطورة:** 🟡 **متوسطة** (قد تسبب هلوسة في حال صياغة خاطئة).
- **خطوات التنفيذ:**
  1. نقوم بفصل ملفات الـ System Prompts في مستندات نصية منفصلة في مسار `/prompts/system_prompt.txt`.
  2. لتجنب إعادة بناء الكود، نبرمج FastAPI ليقوم بقراءة ملف النص من الـ Disk مع كل دورة محادثة أو تخزينها مؤقتاً في Redis مع وقت انتهاء (TTL: 5 minutes).
  3. لتغيير الموجه، نقوم بتعديل الملف ورفعه ومسح كاش Redis الخاص به ليقوم النظام بالتقاط الموجه الجديد فوراً خلال دقائق معدودة.
- **التحقق من النجاح:** خوض محادثة تجريبية مع المساعد للتحقق من التزام المساعد بأسلوب الموجه الجديد.
