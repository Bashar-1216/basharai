## 1. Backup & Recovery Overview

تهدف خطة **النسخ الاحتياطي والاستعادة (Backup & Recovery)** إلى حماية محتوى تدوينات الموقع، وبيانات المشاريع، وسجلات المحادثات والتقييمات من الفقدان العشوائي أو التلف البرمجي، مع صياغة أهداف واضحة لسرعة التعافي:

- **RTO (Recovery Time Objective):** أقل من **15 دقيقة** لاستعادة الموقع للعمل بالكامل بعد انهيار الخادم.
- **RPO (Recovery Point Objective):** أقل من **24 ساعة** (أقصى قدر مقبول لفقد البيانات هو يوم واحد فقط من السجلات).

## 2. PostgreSQL Backup Strategy (pg_dump)

نقوم بتهيئة مهمة مجدولة تلقائية (Cron Job) لتصدير كامل محتويات قاعدة البيانات وعلاقات المتجهات:

- **أداة التصدير:** استخدام الأداة القياسية لـ Postgres `pg_dump`.
- **الجدولة (Schedule):** تعمل المهمة يومياً الساعة **02:00 صباحاً بتوقيت الخليج (UTC+3)** لتفادي أوقات الذروة للزوار ومديري التوظيف.
- **أمر التصدير المؤتمت:**
  ```bash
  pg_dump -U local_developer -h database -d bashar_db -F c -b -v -f /backups/bashar_db_$(date +%F).dump
  ```
  *(تسمح الصيغة `-F c` بضغط الملف واستيراده بشكل انتقائي وسريع لاحقاً).*

## 3. Retention & Storage Policy | الحفظ والتخزين الآمن

لتفادي تضخم التكاليف وحفظ البيانات بشكل آمن:
- **مكان الحفظ (Storage Destination):** يتم رفع ملف الـ Dump آلياً بعد تشفيره إلى حاوية تخزين سحابية مغلقة وآمنة (AWS S3 Glacier أو GitHub private storage artifact).
- **سياسة الحفظ والتدوير (Retention Policy):**
  - الاحتفاظ بنسخ الاستيراد اليومية لآخر **7 أيام متتالية**.
  - الاحتفاظ بنسخ الاستيراد الأسبوعية لآخر **4 أسابيع**.
  - حذف النسخ الأقدم تلقائياً لتوفير المساحة المالية.

## 4. Disaster Recovery (DR) Runbook | خطوات الاستعادة الطارئة

في حال تلف قاعدة البيانات بالكامل أو انهيار حاوية Railway:

### الخطوة 1: إعادة بناء الجداول والمخطط الأصلي
```bash
# Force Prisma schema to rebuild clean database structures
pnpm prisma db push
```

### الخطوة 2: استيراد ملف النسخة الاحتياطية (pg_restore)
قم بتحميل آخر ملف dump مستقر من حاوية التخزين السحابية ونفّذ الأمر التالي:
```bash
pg_restore -U local_developer -h database -d bashar_db -v /backups/latest_stable_backup.dump
```

### الخطوة 3: إعادة بناء فهارس المتجهات
تأكيد استدعاء أمر إعادة توليد فهارس HNSW لتسريع البحث المتجهي:
```sql
REINDEX INDEX idx_interaction_log_vector;
```

## 5. Backup Integrity Auditing

لمنع اكتشاف تلف ملفات النسخ الاحتياطي في وقت الكارثة (Corrupted backups):
- نعد كود فحص مؤتمت بسيط يعمل أسبوعياً للتحقق من أن حجم ملف الـ dump المرفوع سحابياً أكبر من الصفر (`Size > 0`) ومطابق لهيكل التسمية القياسي، وفي حال وجود خلل يتم إرسال تنبيه `CRITICAL` فوراً للمسؤول.
