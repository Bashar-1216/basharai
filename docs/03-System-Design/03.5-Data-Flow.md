## 1. Introduction

يقدم هذا المستند **تدفق البيانات التفصيلي عبر مكونات النظام (Data Flow)**، موضحاً كيفية تحرك طلبات البيانات والاستجابات بين واجهات المستخدم الأمامية وبوابات الـ APIs وقواعد البيانات وخوادم الكاش والذكاء الاصطناعي مع توضيح الفوارق بين حالات وجود البيانات في الذاكرة المؤقتة (Cache Hit) أو تعذر وجودها (Cache Miss).

## 2. Content Request Data Flow (CDN Caching)

يصف المخطط التالي تدفق طلب زائر لصفحة دراسة حالة مشروع أو مقال مدونة (ثابتة):

```mermaid
flowchart TD
    %% Styling definitions
    classDef client fill:#f3f4f6,stroke:#374151,stroke-width:2px;
    classDef cdn fill:#3b82f6,stroke:#1d4ed8,stroke-width:2px,color:#fff;
    classDef origin fill:#10b981,stroke:#047857,stroke-width:2px,color:#fff;

    Start([Visitor GET /projects/rag-assistant]) --> CDNCheck{CDN Edge Cache Hit?}:::cdn
    
    CDNCheck -- Yes (p50 < 30ms) --> ReturnStatic[1. Deliver Pre-rendered HTML + Optimized Assets]:::cdn
    ReturnStatic --> EndPublic([Page Loaded successfully])
    
    CDNCheck -- No (Cache Miss / Stale) --> FetchOrigin[2. Forward request to Next.js Origin Server]:::origin
    FetchOrigin --> ReadMDX[3. Load local MDX content file from Git]:::origin
    ReadMDX --> RenderPage[4. Compile MDX to React Components]:::origin
    RenderPage --> UpdateCDN[5. Cache rendered page on Edge CDN]:::cdn
    UpdateCDN --> ReturnStatic
```

## 3. RAG Query Data Flow (AI Assistant Chat)

هذا هو التدفق الديناميكي الأهم للذكاء الاصطناعي، ويوضح حماية الطلب بالكاش والتقييد قبل تشغيل خوارزميات الـ RAG:

```mermaid
flowchart TD
    %% Styling definitions
    classDef browser fill:#f3f4f6,stroke:#374151,stroke-width:2px;
    classDef next fill:#3b82f6,stroke:#1d4ed8,stroke-width:2px,color:#fff;
    classDef redis fill:#d97706,stroke:#b45309,stroke-width:2px,color:#fff;
    classDef py fill:#10b981,stroke:#047857,stroke-width:2px,color:#fff;
    classDef openai fill:#4b5563,stroke:#1f2937,stroke-width:2px,color:#fff;

    User([User Sends Message]) --> NextBFF[1. Next.js BFF Route Handler]:::next
    NextBFF --> RateLimit{Rate Limit OK in Redis?}:::redis
    
    RateLimit -- No (Limit Exceeded) --> Return429[2. Return HTTP 429 Rate Limit error JSON]:::next
    RateLimit -- Yes --> QueryCache{Query Cache Hit in Redis?}:::redis
    
    QueryCache -- Yes (Cached response) --> StreamCached[3. Stream Cached Text back to Browser]:::next
    QueryCache -- No (Cache Miss) --> ForwardFastAPI[4. Forward query to FastAPI Backend via HTTP]:::py
    
    ForwardFastAPI --> EmbedQuery[5. Convert Query to Vector via OpenAI Embed API]:::openai
    EmbedQuery --> VectorSearch[6. Perform Similarity Search in pgvector PostgreSQL]:::py
    
    VectorSearch --> FormatPrompt[7. Inject retrieved text blocks into System Prompt template]:::py
    FormatPrompt --> SendLLM[8. Request Streaming generation from OpenAI GPT-4o-mini]:::openai
    
    SendLLM --> StreamSSE[9. Stream Response Chunks to Next.js BFF]:::py
    StreamSSE --> SaveCache[10. Cache final generated answer in Redis]:::redis
    StreamSSE --> LogDB[11. Log latency, cost, and metadata to PostgreSQL]:::py
    StreamSSE --> ReturnBrowser[12. Stream text chunks dynamically to Browser]:::next
```

## 4. Admin Observatory Query Data Flow (Dashboard Analytics)

يصف المخطط التالي كيفية سحب وعرض بيانات المراقبة والتحليل للمسؤول:

```mermaid
sequenceDiagram
    autonumber
    actor Admin as Whitelisted Administrator
    participant Browser as Admin Browser
    participant Next as Next.js BFF
    participant FastAPI as FastAPI Backend
    participant DB as PostgreSQL Analytics

    Admin->>Browser: Click Observability Dashboard tab
    Browser->>Next: GET /api/admin/observability/stats
    Next->>Next: Check session token JWT in cookie
    Next->>FastAPI: GET /api/v1/observability/stats (Authorization Bearer Token)
    FastAPI->>FastAPI: Validate JWT signature
    FastAPI->>DB: Query Aggregated Metrics (SELECT SUM(cost), AVG(latency)...)
    DB-->>FastAPI: Return Query Result dataset
    FastAPI->>FastAPI: Format metrics into structured chart JSON
    FastAPI-->>Next: Return status payload
    Next-->>Browser: Render interactive charts (Recharts)
```

## 5. Error & Fallback Data Flows

في حال فشل الوصول لقاعدة البيانات أو تعذر الاتصال بـ Redis:

- **Redis Offline (Rate Limiter Fallback):**
  - عند فشل الاتصال بـ Redis، يتم تمرير طلب المستخدم وتخطي خطوة الـ Rate limit مؤقتاً (Fail-Open) لضمان عدم حجب الزوار الحقيقيين، مع تسجيل تحذير `WARNING` في السجلات لإصلاح الخادم.
- **Database Connection Failure:**
  - إذا تعذر الاتصال بقاعدة البيانات أثناء محاولة البحث المتجهي RAG، يتراجع خادم FastAPI لإرسال السؤال مباشرة إلى OpenAI كـ **محادثة عامة ومجردة (Vanilla LLM Chat)** مع إلحاق تنبيه يعتذر للمستخدم عن عدم القدرة على البحث في الوثائق الدقيقة حالياً.
