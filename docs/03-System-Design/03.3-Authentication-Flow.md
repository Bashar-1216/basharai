## 1. Introduction

يقدم هذا المستند **تدفقات عمليات المصادقة والتحقق بالتفصيل (Authentication Flow)**، مبيناً مسارات تسجيل الدخول للمسؤولين وحماية المسارات المغلقة، وآلية المصادقة والتحقق ثنائية الخدمات بين خوادم Next.js و FastAPI، وكيفية تصفية طلبات الزوار للحد من الاستهلاك (Rate Limiting).

## 2. OAuth Sign-in & Whitelist Verification Flow

يصف مخطط التسلسل التالي مسار تسجيل دخول المسؤول باستخدام Google أو GitHub والتحقق الإجباري من القائمة البيضاء (Whitelist) لمنع دخول الغرباء:

```mermaid
sequenceDiagram
    autonumber
    actor Admin as Administrator
    participant Browser as Web Browser
    participant Next as Next.js BFF
    participant Provider as OAuth Provider (Google/GitHub)
    participant Redis as Upstash Redis

    Admin->>Browser: Access /admin or click Sign In
    Browser->>Next: GET /api/auth/signin/[provider]
    Next-->>Browser: Redirect to OAuth Consent Page
    Browser->>Provider: Show Consent Page / Ask Credentials
    Admin->>Provider: Enter login details & MFA (if any)
    Provider-->>Browser: Redirect back with Auth Code
    Browser->>Next: GET /api/auth/callback/[provider]?code=XYZ
    Next->>Provider: Exchange code for Access Token
    Provider-->>Next: Return User Email & Profile info
    
    Note over Next: Critical Security Whitelist check
    Next->>Next: Compare Email against ADMIN_EMAIL_WHITELIST env var
    
    alt Email is whitelisted
        Next->>Next: Encrypt JWE Session Token
        Next->>Redis: Cache session key for active verification
        Next->>Browser: Set __Secure-next-auth.session-token Cookie (HttpOnly, Secure)
        Browser-->>Admin: Redirect to /admin (Dashboard Loaded)
    else Email is NOT whitelisted
        Next->>Browser: Redirect to /auth/error?reason=AccessDenied
        Browser-->>Admin: Display "Unauthorized Access" error page
    end
```

## 3. Admin Route Protection Middleware Flow

تجري هذه العملية فوراً في طبقة Edge Middleware مع كل طلب وصول لـ `/admin` للتحقق من الجلسة في زمن استجابة سريع للغاية:

```mermaid
flowchart TD
    %% Styling definitions
    classDef process fill:#3b82f6,stroke:#1d4ed8,stroke-width:2px,color:#fff;
    classDef check fill:#eab308,stroke:#ca8a04,stroke-width:2px,color:#333;
    classDef action fill:#10b981,stroke:#047857,stroke-width:2px,color:#fff;

    Start([Request to /admin/path]) --> ReadCookie[1. Read session token Cookie]:::process
    ReadCookie --> HasCookie{Has Cookie?}:::check
    
    HasCookie -- No --> RedirectLogin[2. Redirect to Sign In Page]:::action
    HasCookie -- Yes --> DecryptToken[3. Decrypt & Verify JWE Signature]:::process
    
    DecryptToken --> IsValid{Is Signature Valid?}:::check
    IsValid -- No (Tampered/Expired) --> RedirectLogin
    IsValid -- Yes --> CheckExpiry{Is Token Expired?}:::check
    
    CheckExpiry -- Yes --> RedirectLogin
    CheckExpiry -- No --> ExtractEmail[4. Extract Email from JWT payload]:::process
    
    ExtractEmail --> CheckWhitelist{Email in ADMIN_EMAIL_WHITELIST?}:::check
    CheckWhitelist -- No --> AccessDenied[5. Redirect to Access Denied Page]:::action
    CheckWhitelist -- Yes --> AllowAccess[6. Allow Request to Proceed to Server Components]:::action
```

## 4. Cross-Service API Authorization (BFF to FastAPI)

عندما يطلب المسؤول المسجل بيانات سرية (مثل تحليلات الرسوم البيانية أو اختبارات التقييم) من خادم FastAPI، تتم المصادقة عبر رأس الـ Authorization:

```mermaid
sequenceDiagram
    autonumber
    actor Admin as Administrator
    participant Browser as Web Browser
    participant Next as Next.js BFF
    participant FastAPI as FastAPI Backend

    Admin->>Browser: Open observability dashboard
    Browser->>Next: GET /api/admin/metrics (Cookie attached)
    Next->>Next: Validate Admin Session (Middleware)
    
    Note over Next, FastAPI: Cross-service request authentication
    Next->>FastAPI: GET /api/v1/metrics (Bearer Auth: NextAuth JWT Token)
    
    FastAPI->>FastAPI: Decrypt JWT using shared secret key
    FastAPI->>FastAPI: Verify signature & check whitelist
    
    alt Verification succeeds
        FastAPI-->>Next: Return metrics payload (JSON)
        Next-->>Browser: Render Dashboard UI
    else Verification fails
        FastAPI-->>Next: HTTP 401 Unauthorized
        Next-->>Browser: Show Auth Error message
    end
```

## 5. Unauthenticated Rate Limiting Flow

لحماية مساعد الـ RAG المجاني من سوء الاستخدام مع الحفاظ على سهولة الوصول للزوار:

```mermaid
flowchart TD
    %% Styling definitions
    classDef process fill:#3b82f6,stroke:#1d4ed8,stroke-width:2px,color:#fff;
    classDef check fill:#eab308,stroke:#ca8a04,stroke-width:2px,color:#333;
    classDef action fill:#10b981,stroke:#047857,stroke-width:2px,color:#fff;
    classDef db fill:#f97316,stroke:#c2410c,stroke-width:2px,color:#fff;

    Start([RAG Message Send]) --> GetClient[1. Extract client IP & User-Agent]:::process
    GetClient --> GenerateFingerprint[2. Hash IP + UA to SHA-256 Fingerprint]:::process
    
    GenerateFingerprint --> QueryRedis[3. Check key in Redis: limit:fingerprint]:::db
    QueryRedis --> KeyExists{Key Exists in Redis?}:::check
    
    KeyExists -- No --> CreateKey[4. Create Redis Key<br/>Set Count = 1, TTL = 1 Hour]:::db
    CreateKey --> ProceedRAG[5. Forward request to FastAPI RAG engine]:::action
    
    KeyExists -- Yes --> CheckLimit{Count >= 5?}:::check
    
    CheckLimit -- No --> IncrementKey[6. Increment Redis Key Value]:::db
    IncrementKey --> ProceedRAG
    
    CheckLimit -- Yes --> RejectRequest[7. Reject Request<br/>Return HTTP 429 Rate Limited<br/>Show countdown timer]:::action
```
