## 1. Bilingual Code Philosophy

يهدف تحديد **معايير البرمجة (Coding Standards)** إلى ضمان بقاء الكود المصدري لمنصة bashar.ai نظيفاً ومنظماً وموثقاً بشكل صحيح ومطابقاً لمعايير الجودة العالمية، مما يجعله بمثابة **دليل هندسي لا يقبل الشك (Engineering Evidence)** على كفاءة المرشح وجودة كتابته البرمجية أمام المقيمين الفنيين.

- **اللغة البرمجية:** يكتب الكود بالكامل باللغة الإنجليزية (المتغيرات، التوابع، الجداول، المجلدات).
- **التوثيق والتعليقات:** تكتب تعليقات الكود بلغة إنجليزية واضحة ومباشرة لتوضيح المبررات البرمجية والقرارات الصعبة (Trade-offs) وليس لشرح ما يفعله الكود بديهياً.

## 2. TypeScript/Frontend Standards (Biome)

نستخدم أداة **Biome** (أداة سريعة جداً مكتوبة بلغة Rust تجمع بين عمل ESLint و Prettier) لتنسيق وفحص كود الواجهة الأمامية Next.js.

### 2.1 قواعد الصرامة (Strictness Rules):
- تفعيل خيار الصرامة Strict Mode في `tsconfig.json` بالكامل.
- **يُمنع استخدام النوع `any` نهائياً.** يجب تعريف كافة الحقول والمخرجات بـ Typescript interfaces صريحة.
- تجنب الاختصارات المخلة وتفضيل الأسماء الواضحة المعبرة عن الوظيفة.

### 2.2 إعدادات التنسيق (Biome Configuration):
```json
// biome.json
{
  "$schema": "https://biomejs.dev/schemas/1.8.3/schema.json",
  "organizeImports": {
    "enabled": true
  },
  "linter": {
    "enabled": true,
    "rules": {
      "recommended": true,
      "style": {
        "noNonNullAssertion": "error"
      },
      "correctness": {
        "noUnusedVariables": "error"
      }
    }
  },
  "formatter": {
    "enabled": true,
    "formatWithErrors": false,
    "indentStyle": "space",
    "indentWidth": 2,
    "lineWidth": 100
  }
}
```

### 2.3 حدود المكونات (RSC vs. Client Components Boundary):
- يمنع استخدام `"use client"` في أعلى الملف إلا إذا كان المكون يحتوي على حالات (`useState`, `useEffect`) أو تحريكات بصرية تفاعلية.
- تفضيل استخدام Server Components قدر الإمكان لتحسين سرعة التحميل ومطابقة الـ SEO.

## 3. Python/Backend Standards (Ruff)

نستخدم أداة **Ruff** (أسرع أداة لفحص وتنسيق Python مكتوبة بلغة Rust) لإدارة وتنسيق كود FastAPI.

### 3.1 قواعد الصرامة والأنماط (Formatting & Type Hinting):
- فرض التلميح اللغوي للأنواع (Type Hinting) بشكل إجباري لكافة التوابع (functions) والـ API routes ومخرجاتها لضمان استقرار التشغيل وتفعيل الفحص الذاتي لـ Pydantic.
- استخدام التنسيق غير المتزامن (`async/await`) لكافة العمليات المتصلة بـ I/O (قاعدة البيانات، OpenAI API، Redis).

### 3.2 إعدادات Ruff:
```toml
# pyproject.toml - Ruff Config
[tool.ruff]
target-version = "py312"
line-length = 88
select = [
    "E",  # pycodestyle errors
    "W",  # pycodestyle warnings
    "F",  # pyflakes
    "I",  # isort (imports grouping)
    "B",  # flake8-bugbear (common bugs picker)
    "UP", # pyupgrade (force modern Python syntax)
]
ignore = []

[tool.ruff.format]
quote-style = "double"
indent-style = "space"
```

## 4. File & Directory Naming System

لتسهيل القراءة وتفادي تشتت المجلدات:

- **مستندات التوثيق (Documentation):** تكتب بأسلوب `XX.Y-Name-Here.md` (أرقام متسلسلة ثم الاسم بالإنجليزية) مثل `02.5-RAG-Architecture.md`.
- **ملفات ومجلدات TypeScript:** تكتب بأسلوب **PascalCase** للمكونات (مثل `ChatWidget.tsx`) وأسلوب **camelCase** للتوابع والـ utilities (مثل `verifySession.ts`).
- **ملفات ومجلدات Python:** تكتب بالكامل بأسلوب **snake_case** (أحرف صغيرة مفصولة بشرطة سفلية) مثل `rag_service.py`.

## 5. Git Hooks & CI Validation Rules

لمنع دخول كود مكسور أو غير منسق إلى مستودع GitHub:
- نستخدم **Husky + lint-staged** لتشغيل فحص Biome وفحص Ruff تلقائياً على الملفات المعدلة فقط (Staged files) قبل السماح بعمل Commit:
  ```json
  // package.json - lint-staged config
  "lint-staged": {
    "src/frontend/**/*.{js,ts,tsx}": "biome check --write",
    "src/backend/**/*.py": "ruff check --fix && ruff format"
  }
  ```
- يفشل الـ build في GitHub Actions مباشرة إذا لم يطابق الكود المدمج هذه القواعد.
