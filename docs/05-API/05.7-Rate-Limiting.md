## 1. Rate Limiting Overview

تهدف سياسة **تحديد معدل الطلبات (Rate Limiting)** إلى حماية خوادم الموقع وقاعدة البيانات من هجمات الإغراق (DDoS) وحماية ميزانية استهلاك الذكاء الاصطناعي (OpenAI API Tokens) من محاولات الاستغلال المتكررة، مع الحفاظ على حرية وصول المستخدمين الطبيعيين للمحتوى دون قيود معقدة.

---

## 2. Throttling Tiers | مستويات التقييد

نقسم الحدود البرمجية للطلبات بناءً على هوية المستخدم ونوع الرابط المستعلم:

| Tier | Target Client | Limit Constraint | Storage Key | Action on Limit |
|------|---------------|------------------|-------------|-----------------|
| **Public RAG Assistant** | Unauthenticated visitors | **5 queries / Hour**<br>1 burst / min | `limit:rag:<fingerprint>` | Return HTTP 429 |
| **Public Static Content** | All visitors | Unlimited (CDN Cache) | — | None |
| **Admin Operations** | Authenticated Admin | **120 requests / min** | `limit:admin:<email>` | Return HTTP 429 |
| **Evaluation Suite** | Admin Trigger | **3 runs / Hour** | `limit:eval:global` | Return HTTP 429 |

## 3. Token Bucket Algorithm & Redis Configuration

نستخدم خوارزمية **خزان الرموز (Token Bucket)** في Redis لتطبيق القيود بكفاءة ودقة عالية:

- **آلية العمل:**
  - يمتلك كل مستخدم خزانًا افتراضيًا يحتوي على عدد محدد من الرموز (Tokens).
  - مع كل طلب RAG، يُسحب رمز واحد من الخزان.
  - إذا كان الخزان فارغاً، يتم رفض الطلب فوراً.
  - يعاد ملء الخزان تلقائياً بمعدل ثابت بمرور الوقت (مثال: رمز واحد كل 12 دقيقة ل RAG Assistant).

### Redis Command Sequence (Atomic Lua Script):
```lua
local key = KEYS[1]
local limit = tonumber(ARGV[1])
local current = tonumber(redis.call('get', key) or "0")

if current + 1 > limit then
    return 0 -- Rejected
else
    redis.call("INCRBY", key, 1)
    if current == 0 then
        redis.call("EXPIRE", key, 3600) -- 1 hour TTL
    end
    return 1 -- Allowed
end
```

## 4. Rate Limiting Headers

لإعلام تطبيقات المتصفح بحالتها التقييدية برمجياً، نرسل الرؤوس المعيارية التالية مع كل استجابة RAG:

- `X-RateLimit-Limit`: الحد الأقصى للطلبات المتاحة في الدورة (مثل 5).
- `X-RateLimit-Remaining`: عدد الطلبات المتبقية للزائر حالياً.
- `X-RateLimit-Reset`: عدد الثواني المتبقية لإعادة تعيين العداد بالكامل.

## 5. Bypass & Whitelist Rules

- **الاتصال الداخلي (BFF Loopback):**
  - يتم استثناء أي طلب قادم من Next.js BFF يحمل رأس `X-Internal-Key` مطابق للمفتاح السري الحقيقي من قيود الـ Rate limit لضمان استمرارية الاتصال الداخلي.
- **عناوين IP للمسؤول (Admin Whitelist):**
  - يمكن للمسؤول تهيئة عناوين IP محددة في لوحة الإعدادات لتخطي قيود الـ Rate limits لتسهيل عمليات التقديم والعروض التقديمية الحية أمام لجان المقابلات الشخصية.
