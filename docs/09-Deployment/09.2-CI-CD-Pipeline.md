## 1. CI/CD Workflow Overview

نستخدم منصة **GitHub Actions** لإدارة خط أنابيب التلقائي بالكامل لضمان جودة الأكواد وحماية النسخ الحية. 

ينقسم خط الأنابيب إلى مسارين:
1. **مسار التحقق (Verify):** يعمل تلقائياً مع كل Pull Request للتحقق من التنسيق والأنواع ونجاح الاختبارات.
2. **مسار النشر (Deploy):** يعمل فور الدمج في فرع `master` لبناء وحزم الأكواد وتصديرها لخوادم Vercel و Railway.

## 2. Verify PR Workflow Configuration (`verify-pr.yml`)

يعمل هذا الملف عند فتح أو تعديل أي طلب دمج (Pull Request) لحظر الأخطاء مبكراً:

```yaml
# .github/workflows/verify-pr.yml
name: Verify Pull Request

on:
  pull_request:
    branches: [ master ]

jobs:
  lint-and-test:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'

      - name: Install pnpm & Frontend Deps
        run: |
          npm install -g pnpm
          cd src/frontend
          pnpm install

      - name: Install Python Dependency Manager (uv)
        run: |
          curl -LsSf https://astral.sh/uv/install.sh | sh
          cd src/backend
          uv venv
          uv pip install -r pyproject.toml

      - name: Run Frontend Biome Check
        run: |
          cd src/frontend
          pnpm biome check .

      - name: Run Backend Ruff Check
        run: |
          cd src/backend
          uv run ruff check .
          uv run ruff format --check .

      - name: Run Frontend Unit Tests
        run: |
          cd src/frontend
          pnpm test:run

      - name: Run Backend Unit Tests (with mocked LLM)
        run: |
          cd src/backend
          uv run pytest tests/
```

## 3. Release Production Workflow Configuration (`deploy-prod.yml`)

يعمل هذا الملف تلقائياً بعد دمج الـ PR بنجاح في فرع `master` لتحديث خوادم الإنتاج:

```yaml
# .github/workflows/deploy-prod.yml
name: Deploy to Production

on:
  push:
    branches: [ master ]

jobs:
  deploy-frontend:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Deploy to Vercel (Production)
        uses: amondnet/vercel-action@v25
        with:
          vercel-token: ${{ secrets.VERCEL_TOKEN }}
          vercel-org-id: ${{ secrets.VERCEL_ORG_ID }}
          vercel-project-id: ${{ secrets.VERCEL_PROJECT_ID }}
          vercel-args: '--prod'

  deploy-backend:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Install Railway CLI
        run: npm install -g @railway/cli

      - name: Deploy to Railway (Production)
        run: |
          railway up --service fastapi-backend
        env:
          RAILWAY_TOKEN: ${{ secrets.RAILWAY_TOKEN }}
```

## 4. Deployment Verification & Health Checks

لتأمين الخوادم ومنع وصول نسخ معطلة للمستخدمين، نضبط الخطوات التالية بعد انتهاء النشر:

- **فحص الصحة (Health Check Probe):**
  - يقوم خادم Railway بطلب رابط `/api/v1/health` الخاص بالحاوية الجديدة للتأكد من استجابتها برقم `200 OK` وجاهزية قاعدة البيانات.
  - إذا لم يرجع الخادم رداً ناجحاً في غضون 30 ثانية، يعتبر النشر فاشلاً ويقوم خادم Railway برفض الترقية آلياً والإبقاء على الحاوية السابقة نشطة (Automatic Rollback).
