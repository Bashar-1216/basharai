## 1. Hybrid Deployment Model

تعتمد منصة bashar.ai على **بنية نشر هجينة (Hybrid Deployment)** تفصل طبقة العرض والـ BFF السريعة عن معالجة الذكاء الاصطناعي الثقيلة وإدارة قاعدة البيانات لتحقيق التوازن بين السرعة الفائقة والتكلفة المنخفضة:

```
                  ┌──────────────────────┐
                  │   DNS: bashar.ai     │
                  └──────────┬───────────┘
                             │
              ┌──────────────┴──────────────┐
              ▼                             ▼
   ┌────────────────────┐        ┌────────────────────┐
   │    Vercel Edge     │        │  Railway Container │
   │  (Next.js Frontend)│        │   (FastAPI RAG)    │
   └────────────────────┘        └──────────┬─────────┘
                                            │
                               ┌────────────┴────────────┐
                               ▼                         ▼
                    ┌────────────────────┐    ┌────────────────────┐
                    │  Railway Postgres  │    │   Railway Redis    │
                    │    (pgvector DB)   │    │    (Rate Limiter)  │
                    └────────────────────┘    └────────────────────┘
```

- **الواجهة الأمامية (Next.js):** يتم نشرها كـ Serverless/Edge Functions على منصة **Vercel** لتقريب محتوى الصفحات الثابتة لزوار دول الخليج والعالم بأدنى كمون.
- **الواجهة الخلفية للذكاء الاصطناعي (FastAPI):** يتم نشرها كـ Docker Container مستقر على منصة **Railway** لتسهيل الاتصال الدائم وحفظ الذاكرة المؤقتة.
- **قواعد البيانات (Postgres & Redis):** يتم استضافتها داخل شبكة Railway الداخلية المؤمنة لمنع تعريض منافذها للإنترنت العام وتقليل زمن استعلام RAG.

## 2. Infrastructure & Cloud Providers

تم اختيار الخوادم ومراكز البيانات لتسريع الوصول الجغرافي للخليج العربي (GCC):

- **موقع الخوادم (Deployment Regions):**
  - **FastAPI Backend (Railway):** يتم نشره في مركز بيانات `eu-central-1` (Frankfurt) لتوفير أقصر مسار لكوابل الاتصالات البحرية المتجهة للشرق الأوسط والخليج.
  - **Vercel Frontend CDN:** تستخدم Vercel خوادم الحافة (Anycast CDN) الموزعة تلقائياً، وتخدم زوار دول الخليج عبر أقرب محطة حافة (Edge Locations) في البحرين ودبي وجدة.

## 3. Zero-Downtime Deployment Flow

لضمان عدم انقطاع الخدمة عن الزوار أو لجان المقابلات أثناء تحديث الموقع:

- **Next.js (Vercel):**
  - تستخدم Vercel النشر الذري (Atomic deployments).
  - يتم بناء النسخة الجديدة بالكامل في الخلفية، وإذا اجتازت الفحوصات، يتم تحويل مسار الـ DNS للنسخة الجديدة في جزء من الثانية (Instant swap).
- **FastAPI (Railway):**
  - نطبق استراتيجية **التدحرج الترقوي (Rolling Deployments / Blue-Green)**.
  - يقوم خادم Railway ببدء الحاوية الجديدة وفحص حالتها (Health Check `/api/v1/health`) أولاً، وإذا أرجعت نجاحاً، يتم تحويل الطلبات إليها تدريجياً وإطفاء الحاوية القديمة دون فقدان أي طلب قيد المعالجة.

## 4. Cost Optimization & Scaling Limits | التحكم بالميزانية

بما أن المشروع حقيبة مهنية شخصية بتمويل ذاتي، تم صياغة البنية لتكلفة تشغيل تقارب الصفر:

- **خطة Vercel:** شريحة الهواة (Hobby Tier) المجانية بالكامل (تغطي حتى 100GB استهلاك شهري وهو ما يفيض عن حاجة المعرض بنسبة 1000%).
- **خطة Railway:** شريحة المطورين (Developer Plan) بتكلفة استهلاك تبدأ من **$5 شهرياً** (تعتمد الحساب الدقيق بالثانية للمعالج والذاكرة المستهلكة).
- **إيقاف الموارد الخاملة:** تهيئة الخادم الخلفي ليتراجع برمجياً إلى حجم موارد ضئيل جداً (`0.1 CPU`, `128MB RAM`) في أوقات الخمول لحماية الميزانية من الهدر.
