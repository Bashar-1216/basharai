## 1. Domain & Subdomain Architecture

لتأكيد احترافية المنصة وتوفير وصول آمن ومنظم، نستخدم النطاق الرئيسي `bashar.ai` ونقسم الروابط كالتالي:

- **النطاق الرئيسي (`bashar.ai`):** موجه لخدمة صفحات Next.js والواجهات البصرية (Vercel edge).
- **نطاق الخدمات الخلفية (`api.bashar.ai`):** موجه لخدمات معالجة الذكاء الاصطناعي FastAPI وقاعدة البيانات (Railway alias).

---

## 2. DNS Records Registry | جدول سجلات النطاق

يتم إعداد وتوجيه السجلات البرمجية عبر لوحة تحكم **Cloudflare DNS** وفق الجدول التالي:

| Record Type | Name | Content / Target | Proxy Status | TTL | Purpose |
|-------------|------|------------------|--------------|-----|---------|
| **CNAME** | `@` (bashar.ai) | `cname.vercel-dns.com` | 🟢 Proxied | Auto | Serves Next.js pages |
| **CNAME** | `www` | `bashar.ai` | 🟢 Proxied | Auto | Redirects www to root |
| **CNAME** | `api` | `fastapi-backend.up.railway.app`| 🔴 DNS Only | Auto | Direct link to FastAPI |
| **TXT** | `@` | `v=spf1 include:_spf.mx.cloudflare.net ~all`| 🔴 DNS Only| Auto | SPF record for secure emails |

*ملاحظة هامة:* يجب تعطيل الـ Cloudflare Proxy (`Proxy Status = DNS Only`) على النطاق الفرعي `api.bashar.ai` لتجنب تعارض مهلات خوادم Cloudflare (Timeouts) مع بث الـ SSE الطويل لـ RAG.

## 3. Cloudflare CDN & Edge Cache Rules

نستغل طبقة Cloudflare CDN القريبة جغرافيًا من دول الخليج العربي لتخزين وتوزيع الملفات الثابتة بسرعة فائقة:

- **قواعد التخزين المؤقت (Cache Rules):**
  - تفعيل التخزين المؤقت الكامل للملفات الساكنة (JS, CSS, WebP, SVG) في خوادم الحافة الخليجية لمدة **30 يوماً**.
  - تجريد ملفات تعريف الجلسة (Stripping cookies) للصور الثابتة لضمان أقصى سرعة تحميل.

## 4. Bypassing Cache for SSE Streaming Routes

- **المشكلة:** قد تحاول شبكات الـ CDN تجميع استجابة الـ RAG chat وبثها دفعة واحدة للمتصفح مما يفقد واجهة المحادثة ميزتها التدريجية الرشيقة.
- **الحل:** ننشئ قاعدة تصفية صريحة (Page Rule / Cache Bypass) في Cloudflare:
  - **المسار:** `bashar.ai/api/v1/chat`
  - **الإجراء:** تفعيل **Cache Level = Bypass** وإيقاف **Brotli/Gzip buffering** على هذا المسار لضمان تدفق الكلمات جزءاً بجزء فور صدورها من خادم FastAPI.

---

## 5. GCC Regional Latency Optimization

- نستخدم خوادم أسماء Cloudflare (Cloudflare Anycast Nameservers) لتقليل زمن استعلام الـ DNS في دول الخليج إلى أقل من **15ms**.
- تفعيل خاصية **Argo Smart Routing** في Cloudflare لتوجيه طلبات RAG من متصفح المستخدم إلى خادم FastAPI (في فرانكفورت) عبر أسرع مسارات كابلات الألياف الضوئية السحابية وتجنب التكدس الشبكي العام.
