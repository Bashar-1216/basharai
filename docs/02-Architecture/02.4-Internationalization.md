## 1. i18n Architecture Overview

وفقاً لـ PRD §3.7، تُعد **اللغة العربية متطلباً أساسياً (First-class requirement)** للمشروع للوصول الفعّال لسوق الخليج العربي (Saudi Arabia / UAE)، وليست مجرد طبقة ترجمة تتم إضافتها بعد انتهاء العمل. تم تصميم معمارية التدويل (i18n) لدعم اللغتين العربية والإنجليزية بشكل متكافئ مع تغيير كامل لاتجاه الموقع وتجربة المستخدم (RTL/LTR).

```
                 ┌──────────────────────────────────────┐
                 │          User Request                │
                 │    (Browser Accept-Language Header)  │
                 └──────────────────┬───────────────────┘
                                    │
                                    ▼
                 ┌──────────────────────────────────────┐
                 │       next-intl Middleware           │
                 │   - Reads /en/ or /ar/ segment       │
                 │   - Detects fallback if root URL     │
                 └──────────────────┬───────────────────┘
                                    │
                  ┌─────────────────┴─────────────────┐
                  ▼                                   ▼
       ┌─────────────────────┐             ┌─────────────────────┐
       │   Arabic (ar-SA)    │             │   English (en-US)   │
       │ - direction: rtl    │             │ - direction: ltr    │
       │ - Font: IBM Plex Ar │             │ - Font: Inter       │
       └─────────────────────┘             └─────────────────────┘
```

## 2. Locale Routing Strategy

نستخدم نظام المجلدات الديناميكي `[locale]` الموفر بواسطة Next.js App Router بالتعاون مع `next-intl`.

- **نطاق الروابط (Route Structure):**
  - `/ar/about` -> النسخة العربية من صفحة السيرة الذاتية.
  - `/en/about` -> النسخة الإنجليزية من صفحة السيرة الذاتية.
  - `/` (الجذر) -> تقوم طبقة الـ Middleware بقراءة لغة المتصفح المفضلة وتحويل المستخدم تلقائياً إلى `/ar` أو `/en` (بشكل افتراضي `/en` إذا لم تكن لغة المتصفح عربية).

- **مفتاح اللغة في Middleware:**
  ```typescript
  // i18n/request.ts
  import {getRequestConfig} from 'next-intl/server';
  
  export default getRequestConfig(async ({locale}) => ({
    messages: (await import(`../messages/${locale}.json`)).default
  }));
  ```

## 3. Translation Management Split

لتفادي تضخم ملفات JSON المخصصة للترجمة وتخريب تجربة المطور، نتبع استراتيجية **الفصل بين المحتوى وواجهة المستخدم (Content/UI Split)**:

```
                            ┌───────────────────┐
                            │  Translation Hub  │
                            └─────────┬─────────┘
                                      │
                  ┌───────────────────┴───────────────────┐
                  ▼                                       ▼
        ┌──────────────────┐                    ┌──────────────────┐
        │  UI Translations │                    │  Content Engine  │
        │  • next-intl JS  │                    │  • Separate MDX  │
        │  • Buttons, Nav  │                    │  • Case Studies  │
        │  • Form Labels   │                    │  • Blog Posts    │
        └──────────────────┘                    └──────────────────┘
```

1. **ترجمات واجهة المستخدم (UI Strings):**
   - تُخزن في مجلد `messages/` في ملفات JSON تقليدية (`en.json`, `ar.json`).
   - تُقرأ داخل المكونات باستخدام `useTranslations` Hook.

2. **المحتوى الطويل (Rich Content):**
   - يُكتب بالكامل في ملفات MDX منفصلة لكل لغة داخل مجلد `content/en/` و `content/ar/`.
   - يضمن ذلك أن تكون لكل لغة صياغتها الخاصة وأمثلتها المحددة (مثل صياغة أثر العمل في أمازون بطريقة مخصصة لجمهور الخليج مقارنة بالجمهور العالمي).

## 4. RTL Layout & Styling Strategy

نعتمد بالكامل على **الخصائص المنطقية (CSS Logical Properties)** و Tailwind CSS 4 المدمج لحل مشاكل اتجاهات التصميم دون الحاجة لإعادة كتابة الأنماط مرتين.

### 4.1 اتجاه الصفحة الرئيسي (HTML Direction):
يتم تحديد اتجاه الموقع ديناميكياً في ملف التخطيط الرئيسي (`app/[locale]/layout.tsx`):
```tsx
export default function LocaleLayout({children, params: {locale}}) {
  const direction = locale === 'ar' ? 'rtl' : 'ltr';
  return (
    <html lang={locale} dir={direction}>
      <body>{children}</body>
    </html>
  );
}
```

### 4.2 Tailwind CSS 4 Logical Properties:
يُمنع استخدام الاتجاهات الصارمة (`mr-`, `pl-`, `left-`, `right-`) ويُستبدل بالخصائص المنطقية المترجمة تلقائياً:

| Physical Property | Logical Equivalent (Tailwind) | Rationale |
|-------------------|-------------------------------|-----------|
| `margin-left` | `ms-` (margin-inline-start) | Moves to the right in RTL |
| `padding-right` | `pe-` (padding-inline-end) | Moves to the left in RTL |
| `border-top-left-radius` | `rounded-ss-` (start-start) | Correctly rounds the top-start corner |
| `left: 0` | `start-0` | Aligns to the start edge dynamically |
| `text-align: left` | `text-start` | Aligns text correctly per language |

## 5. Bilingual Typography System

الخطوط العربية السيئة تقتل تصميم الموقع وتوحي بعدم الاحترافية. تم تصميم نظام طباعة مخصص يختار أفضل الخطوط لكل لغة مع محاذاة ارتفاع الأسطر (Line Heights) لضمان التوازن البصري.

- **الخط الإنجليزي (English Font):**
  - **Inter (Variable Font):** خط هندسي معاصر يناسب المظهر الرقمي التقني المتقدم.
- **الخط العربي (Arabic Font):**
  - **IBM Plex Sans Arabic (Variable Font):** خط عربي حديث جداً، يجمع بين المظهر التقني وأصالة الحروف العربية، ويتميز بوضوح قراءته الاستثنائي على الشاشات الصغيرة وارتفاع حروفه المتناسق بـ (X-height) مع خط Inter.

### Font Loading Configuration:
```typescript
// styles/fonts.ts
import { Inter } from 'next/font/google';
import { IBM_Plex_Sans_Arabic } from 'next/font/google';

export const inter = Inter({
  subsets: ['latin'],
  variable: '--font-inter',
  display: 'swap',
});

export const ibmPlexArabic = IBM_Plex_Sans_Arabic({
  subsets: ['arabic'],
  weight: ['300', '400', '500', '600', '700'],
  variable: '--font-arabic',
  display: 'swap',
});
```

يتم دمج الخطوط ديناميكياً في فئات CSS المتغيرة بناءً على لغة الصفحة الحالية.

## 6. Localization Formatters (Dates, Numbers, Currencies)

تختلف طريقة قراءة التواريخ والأرقام في دول الخليج عن المعايير الغربية. نستخدم كائن `Intl` البرمجي المدمج في المتصفحات لضمان دقة التنسيق.

- **الأرقام (Numbers):**
  - في اللغة العربية، نستخدم الأرقام العربية الشرقية (1, 2, 3) أو الأرقام الهندية (١, ٢, ٣) بناءً على تفضيل السوق المستهدف. يُفضل استخدام الأرقام القياسية (1, 2, 3) في السياقات التقنية.
- **التواريخ (Dates):**
  - لعرض فترات العمل في الشركات (أمازون/جرامرلي):
    - بالإنجليزية: `July 2026`
    - بالعربية: `يوليو ٢٠٢٦` (أو يوليو 2026) باستخدام تنسيق `ar-SA` أو `ar-EG` المخصص عبر `next-intl` formatters.

## 7. Bilingual SEO & Meta Configuration

لتجنب مشاكل المحتوى المكرر وفهرسة محركات البحث بشكل صحيح في دول الخليج:

1. **hreflang Tags:**
   توليد وسوم الارتباط التلقائية للإشارة إلى وجود نسختين من الصفحة:
   ```html
   <link rel="alternate" hreflang="en" href="https://bashar.ai/en/about" />
   <link rel="alternate" hreflang="ar" href="https://bashar.ai/ar/about" />
   <link rel="alternate" hreflang="x-default" href="https://bashar.ai/en/about" />
   ```
2. **Dynamic Metadata:**
   تحميل العناوين والأوصاف المخصصة لكل لغة لزيادة معدل النقر للظهور (CTR) في نتائج البحث المحلية.

## 8. Bidirectional (BiDi) Text & Text Expansion

- **مشكلة تمدد النص (Text Expansion):**
  - غالباً ما تكون النصوص المترجمة إلى العربية أطول أو أقصر بنسبة تتراوح بين **15% إلى 25%** من النسخة الإنجليزية.
  - تم تصميم صناديق المكونات (Layout Containers) بهوامش مرنة (Flexbox/Grid gap) تمنع تداخل النصوص عند التغيير بين اللغتين.
- **النصوص مختلطة الاتجاه (Bidirectional Text):**
  - عند كتابة مصطلحات إنجليزية داخل نص عربي (مثال: "بنيت نظام RAG متقدم باستخدام LangChain")، قد يحدث خلل في ترتيب علامات الترقيم.
  - نستخدم خاصية CSS `unicode-bidi: plaintext` أو وسم HTML `<bdi>` لمعالجة النصوص المختلطة وتثبيت اتجاهها الصحيح.

## 9. LLM Language Matching (RAG i18n)

أحد أهم جوانب التدويل في هذا المشروع هو سلوك **مساعد الذكاء الاصطناعي (Epic E1)**:

1. **كشف لغة الاستعلام (Language Detection):**
   - يقوم المساعد بقراءة لغة سؤال الزائر فور إرساله (عبر فحص ترميز الحروف أو استعلام سريع للنموذج).
2. **توليد الإجابة بنفس لغة السؤال:**
   - إذا سأل المستخدم بالعربية، يجب أن تتم الإجابة باللغة العربية الفصحى السليمة، حتى لو كان السياق المسترجع (Context) من قاعدة البيانات باللغة الإنجليزية.
3. **توفير السياق ثنائي اللغة:**
   - تدعم قاعدة البيانات (pgvector) تخزين وتضمين المحتوى باللغتين، ويقوم محرك البحث المتجهي باسترجاع أفضل المستندات ذات الصلة بالدلالة اللغوية المناسبة.

## 10. RTL Testing & Parity Verification

لضمان جودة التعريب وعدم تعطل التصميم:
- **Visual Regression Testing:**
  اختبار توافق الشاشات وتصويرها آلياً في اللغتين لضمان عدم وجود أزرار خارج الحدود أو نصوص متداخلة.
- **Content Parity Enforcement:**
  مراجعة مستودع المحتوى (Content Repository) للتأكد من أن كل ملف مضاف في `content/en/` يمتلك ملفًا رديفًا بنفس الاسم وبترجمة دقيقة في `content/ar/`.
