## 1. Configuration Methodology (12-Factor App)

نتبع في مشروع bashar.ai منهجية **تطبيقات العوامل الاثني عشر (12-Factor App Methodology)** وتحديداً العامل الثالث: **التهيئة (Config)**:

> "تخزين الإعدادات والتهيئة في متغيرات البيئة (Environment Variables) بالكامل وبشكل مستقل عن كود التطبيق".

يضمن هذا الأسلوب إمكانية ترحيل التطبيق ونشره بين بيئات التشغيل المختلفة (التطوير المحلي، بيئة المعاينة Staging، بيئة الإنتاج Production) دون الحاجة لتغيير سطر برمجى واحد في الكود، مع المحافظة التامة على سرية البيانات الحساسة والمفاتيح البرمجية.

## 2. Environment Variable Strategy

نقوم بتقسيم متغيرات البيئة بناءً على الصلاحيات وحاجة المكونات إليها:

1. **المتغيرات الخاصة بالمتصفح (Public/Client Env Vars):**
   - تُعرف في Next.js بالبادئة `NEXT_PUBLIC_` (مثل `NEXT_PUBLIC_API_URL`).
   - يقوم Next.js بدمج هذه المتغيرات في كود JavaScript المرسل للمتصفح أثناء عملية البناء (Build time).
2. **المتغيرات الخاصة بالخادم (Private/Server Env Vars):**
   - لا تحتوي على أي بادئات خاصة وتكون سرية ومخفية بالكامل عن المتصفح (مثل `DATABASE_URL` و `OPENAI_API_KEY`).
   - لا يمكن قراءتها إلا داخل كود Next.js API Routes أو خادم FastAPI.

## 3. Required Environment Variables Inventory

توضح الجداول التالية كافة متغيرات البيئة المطلوبة لتشغيل خوادم المشروع:

### 3.1 الواجهة الأمامية (Next.js - Frontend & BFF)

| Variable Name | Required | Default / Example | Purpose |
|---------------|----------|-------------------|---------|
| `NEXT_PUBLIC_SITE_URL` | Yes | `https://bashar.ai` | Used for absolute link generation and SEO tags. |
| `NEXT_PUBLIC_API_URL` | Yes | `https://api.bashar.ai` | Target endpoint for RAG API requests. |
| `NEXTAUTH_SECRET` | Yes | `generate-uuid-v4-secret` | Encryption key for Session JWEs. |
| `NEXTAUTH_URL` | Yes | `https://bashar.ai/api/auth` | Callback endpoint for OAuth redirects. |
| `GOOGLE_CLIENT_ID` | Yes | `google-oauth-client-id` | Admin Authentication credential. |
| `GOOGLE_CLIENT_SECRET` | Yes | `google-oauth-secret` | Admin Authentication credential. |
| `ADMIN_EMAIL_WHITELIST` | Yes | `owner@bashar.ai` | Comma-separated list of approved admin emails. |

### 3.2 الواجهة الخلفية (FastAPI - AI Service)

| Variable Name | Required | Default / Example | Purpose |
|---------------|----------|-------------------|---------|
| `FASTAPI_ENV` | Yes | `production` / `development` | Switches logging formats and error verbose. |
| `DATABASE_URL` | Yes | `postgresql://user:pass@host:5432/db` | Connection string for SQLAlchemy ORM. |
| `REDIS_URL` | Yes | `redis://:pass@host:6379/0` | Cache, queues, and rate-limiting store. |
| `OPENAI_API_KEY` | Yes | `sk-proj-...` | RAG generation and embeddings token. |
| `INTERNAL_API_KEY` | Yes | `long-secure-random-token` | Shares API secret for BFF validation checks. |
| `LANGCHAIN_TRACING_V2` | No | `true` | Toggles LangSmith tracing hooks. |
| `LANGCHAIN_API_KEY` | No | `lsv2_pt_...` | Authentication for LangSmith account dashboard. |

## 4. Secrets Protection & Rotation Policy

- **تخزين الأسرار (Secrets Storage):**
  - **محلياً:** تُحفظ الأسرار في ملف `.env.local` غير المتتبع في Git والمدرج بالكامل في `.gitignore`.
  - **سحابياً:** يتم استدعاء الأسرار من لوحة مفاتيح Vercel المروّسة و Railway Encrypted Environment UI.
- **سياسة التدويل والتبديل (Rotation Policy):**
  - يتم استبدال مفاتيح الـ API التابعة لـ OpenAI و Google OAuth كل 180 يوماً بشكل إجباري، أو فوراً في حال الاشتباه في وجود أي تسرب أو استخدام غير مصرح به.

## 5. Feature Flagging Architecture

لتسهيل تجارب النشر التدريجي وإيقاف الخدمات المتعطلة بشكل فوري دون الحاجة لإعادة البناء والنشر (Deployment):
- نستخدم متغيرات بيئية مخصصة كـ **أعلام مزايا (Feature Flags)** بسيطة:
  - `FEATURE_CHAT_ENABLED`: تفعيل أو إيقاف نافذة المساعد الذكي.
  - `FEATURE_EVAL_DASHBOARD`: تفعيل أو إخفاء لوحة مقاييس المراقبة العامة.
- يقرأ كود التطبيق هذه المتغيرات ويخفي المكونات المعنية تلقائياً في حال كانت القيمة `false`.

## 6. Configuration Validation & Fail-Fast Pattern

لمنع وقوع أخطاء تشغيل غامضة في بيئة الإنتاج نتيجة نسيان إعداد متغير بيئي معين، نتبع أسلوب **الفشل الفوري عند التشغيل (Fail-Fast Startup Validation)**:

### 6.1 الواجهة الأمامية (Next.js Env Validation via Zod):
```typescript
// src/frontend/lib/env.ts
import { z } from 'zod';

const envSchema = z.object({
  NEXT_PUBLIC_SITE_URL: z.string().url(),
  NEXT_PUBLIC_API_URL: z.string().url(),
  NEXTAUTH_SECRET: z.string().min(16),
  ADMIN_EMAIL_WHITELIST: z.string(),
});

export const env = envSchema.parse(process.env);
```
يفشل البناء (Build) مباشرة إذا لم تطابق المدخلات الشروط المحددة.

### 6.2 الواجهة الخلفية (FastAPI validation via Pydantic):
```python
# src/backend/app/core/config.py
from pydantic import PostgresDsn, RedisDsn, SecretStr
from pydantic_settings import BaseSettings

class Settings(BaseSettings):
    FASTAPI_ENV: str = "production"
    DATABASE_URL: PostgresDsn
    REDIS_URL: RedisDsn
    OPENAI_API_KEY: SecretStr
    INTERNAL_API_KEY: SecretStr

    class Config:
        env_file = ".env"

settings = Settings()
```
يفشل الخادم في بدء التشغيل كلياً (Crashes immediately) إذا فقد أحد المتغيرات المطلوبة.

## 7. Local Docker Compose Configuration

نوفر ملف `docker-compose.yml` كامل لتسهيل محاكاة بيئة الإنتاج محلياً بضغطة زر واحدة:

```yaml
version: '3.8'

services:
  database:
    image: ankane/pgvector:v0.5.1 # PostgreSQL 15/16 loaded with pgvector
    ports:
      - "5432:5432"
    environment:
      POSTGRES_USER: local_developer
      POSTGRES_PASSWORD: local_secure_password
      POSTGRES_DB: bashar_db
    volumes:
      - pgdata:/var/lib/postgresql/data

  redis:
    image: redis:7.2-alpine
    ports:
      - "6379:6379"
    volumes:
      - redisdata:/data

  backend:
    build:
      context: ./src/backend
      dockerfile: Dockerfile
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://local_developer:local_secure_password@database:5432/bashar_db
      - REDIS_URL=redis://redis:6379/0
      - OPENAI_API_KEY=${OPENAI_API_KEY} # Passed from host env
      - INTERNAL_API_KEY=local_internal_secret_token
    depends_on:
      - database
      - redis

volumes:
  pgdata:
  redisdata:
```

يسمح هذا الملف البرمجي للمطور بتشغيل كامل البنية التحتية وقواعد البيانات المتجهية بطلب أمر واحد: `docker compose up -d`.
