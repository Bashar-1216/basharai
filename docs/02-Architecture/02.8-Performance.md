## 1. Performance Budget & Targets

تُعد سرعة استجابة الموقع جزءاً رئيسياً من **الأدلة الهندسية (Engineering Evidence)** المعروضة للمقّيمين الفنيين في شركات التقنية الكبرى ودول الخليج. لقد وضعنا ميزانية أداء صارمة تستهدف متطلبات Core Web Vitals وتضمن أداءً فائق السرعة على الهواتف والأجهزة اللوحية.

### Core Web Vitals & Lighthouse Targets

| Metric | Target | Description | Rationale |
|--------|--------|-------------|-----------|
| **LCP** (Largest Contentful Paint) | **< 1.8s** | Time for the main content to load. | Keeps bounce rates extremely low. |
| **INP** (Interaction to Next Paint) | **< 150ms** | Visual feedback latency after interaction. | Critical for a smooth chat widget feel. |
| **CLS** (Cumulative Layout Shift) | **< 0.05** | Visual stability of page elements. | Prevents annoying layout shifts during i18n switches. |
| **Lighthouse Score** | **95+** | Performance, Accessibility, Best Practices, SEO | Demonstrates production quality. |

## 2. Multi-Layer Caching Strategy

نعتمد على استراتيجية تخزين مؤقت متعددة المستويات لتقليل فترات الانتظار وخفض استهلاك قاعدة البيانات والـ APIs الخارجية.

```
                  ┌─────────────────────────────────────┐
                  │          Browser Cache              │
                  │   - Service Worker (Static MDX)     │
                  └──────────────────┬──────────────────┘
                                     │ (Miss)
                                     ▼
                  ┌─────────────────────────────────────┐
                  │           CDN Edge Cache            │
                  │   - Vercel Edge Cache (SSG Pages)   │
                  └──────────────────┬──────────────────┘
                                     │ (Miss)
                                     ▼
                  ┌─────────────────────────────────────┐
                  │            Redis Cache              │
                  │   - API Responses / RAG query cache │
                  └──────────────────┬──────────────────┘
                                     │ (Miss)
                                     ▼
                  ┌─────────────────────────────────────┐
                  │          Database & Origin          │
                  │   - PostgreSQL query execution      │
                  └─────────────────────────────────────┘
```

1. **الطبقة الأولى: تخزين المتصفح (Browser Cache):**
   - تُخزن الأصول الثابتة (الخطوط، الأيقونات) بـ Cache Control طويل ومستقر.
2. **الطبقة الثانية: شبكة CDN (Vercel Edge):**
   - يتم تخزين صفحات دراسات الحالة والخبرة المهنية الثابتة على الحافة (Edge PoPs) للتوصيل الفوري للزوار القريبين.
3. **الطبقة الثالثة: ذاكرة الكاش الموزعة (Redis):**
   - تخزين نتائج طلبات RAG المتكررة وأسئلة الزوار لمدة **5 دقائق**. هذا يوفر ما يصل إلى **40%** من تكاليف OpenAI API ويمنع الهجمات المتكررة.

## 3. Static Generation Strategy (SSG/ISR/SSR)

يتم تقسيم الموقع بناءً على متطلبات الديناميكية لضمان سرعة التحميل دون التضحية بالوظائف التفاعلية:

| Page / Component | Strategy | Revalidation Frequency | Rationale |
|------------------|----------|------------------------|-----------|
| **Landing & About Pages** | **SSG** (Static Site Generation) | At build time | Zero database calls at request time, immediate delivery. |
| **Experience & Projects Content** | **SSG** | At build time | Built from MDX files locally in Git. Maximum SEO and performance. |
| **Blog Index & Posts** | **ISR** (Incremental Static Regeneration) | 24 Hours / On-Demand webhook | Static delivery, updates automatically when content changes. |
| **Admin Observability Dashboard** | **SSR** (Server-Side Rendering) | Per request (no caching) | Real-time graphs and cost monitoring. Must be live. |
| **Chat Assistant UI** | **Client Component** | Dynamic (streaming) | Interactive UI component with state. |

## 4. Image & Asset Optimization

- **Next.js Image Component (`next/image`):**
  - نستخدم المكون الافتراضي الذي يضمن:
    - **التنسيق التلقائي:** تحويل الصور لصيغة WebP أو AVIF إذا كان المتصفح يدعمها.
    - **حجم مستجيب:** توليد وسوم `srcset` لتقديم الحجم المناسب لكل شاشة.
    - **تحميل كسول (Lazy Loading):** لا يتم تحميل الصور الواقعة أسفل خط الطي (below-fold) إلا عند اقتراب المستخدم منها.
- **تأثير الضبابية (Blur Placeholders):**
  - نولد صور مصغرة ضبابية مدمجة (Base64) لتظهر أثناء تحميل الصورة الأصلية، مما يمنع حدوث CLS (Layout Shift) ويحسن تجربة الانتظار.

## 5. Font & Typography Loading

- **إلغاء فترات الانتظار للخطوط (Zero Layout Shift):**
  - نستخدم `@next/font` لتحميل الخطوط (Inter و IBM Plex Sans Arabic).
  - يتم دمج الخطوط تلقائياً في ملفات CSS كـ **Variable Fonts** لتقليل حجم التحميل الإجمالي (تحميل ملف واحد مرن بدلاً من 5 ملفات لأوزان الخط المختلفة).
- **التصفية اللغوية (Subsetting):**
  - نقوم بتحميل مجموعات الأحرف المطلوبة فقط (اللاتينية والعربية) واستبعاد اللغات والرموز غير المستخدمة، مما يوفر ما يصل إلى **60%** من حجم ملف الخط.

## 6. Bundle Size & Code Splitting

- **تقطيع الكود التلقائي (Automatic Code Splitting):**
  - يقوم Next.js App Router بتقطيع الكود برمجياً بناءً على المسارات (Routes)، بحيث لا يتم تحميل كود صفحة `/admin` عند زيارة الصفحة الرئيسية.
- **التحميل الديناميكي (Dynamic Imports):**
  - المكونات الثقيلة التي لا نحتاجها فوراً (مثل مكتبات الرسوم البيانية كـ Recharts في لوحة التحكم، أو واجهة محرر النصوص في CMS) يتم تحميلها ديناميكياً فقط عند فتح التبويب الخاص بها:
    ```tsx
    const AnalyticsCharts = dynamic(() => import('@/components/admin/Charts'), {
      ssr: false,
      loading: () => <SkeletonLoader />
    });
    ```

## 7. GCC-Specific Optimization

لتحسين السرعة وجودة الاتصال للجمهور المستهدف في دول الخليج:
- **Middle East PoP Routing:**
  - يتم تهيئة استعلامات CDN Edge للارتباط مباشرة بخوادم دبي والمنامة، مما يخفض زمن الاستجابة للملفات الثابتة لزوار السعودية والإمارات إلى أقل من **30ms**.
- **Preconnect Hints:**
  - نقوم بإدراج وسوم `preconnect` و `dns-prefetch` للخدمات الخارجية الحرجة (مثل OpenAI API و NextAuth Providers) لبدء اتصال TCP/TLS مبكراً قبل إرسال أول طلب RAG فعلي.

## 8. Backend & Database Performance

- **FastAPI Async Engine:**
  - تمت كتابة كافة منافذ FastAPI بطريقة غير متزامنة بالكامل (`async/await`) للتعامل مع آلاف الاتصالات المتزامنة دون إعاقة الخادم (Blocking).
- **Connection Pooling:**
  - نستخدم SQLAlchemy connection pooling لـ FastAPI و Connection Pooling المدمج في Prisma لـ Next.js لمنع استنزاف ذاكرة خادم PostgreSQL.
- **Index Tuning (pgvector):**
  - يتم ضبط معامل `m` و `ef_construction` في فهرس HNSW الخاص بـ pgvector للوصول لأفضل توازن بين سرعة الاسترجاع وفترة البناء (build time):
    ```sql
    CREATE INDEX ON items USING hnsw (embedding vector_cosine_ops) WITH (m = 16, ef_construction = 64);
    ```
