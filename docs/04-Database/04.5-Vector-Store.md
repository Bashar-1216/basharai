## 1. Vector Database Technology Decision

وفقاً لعمارة المشروع، تم اختيار إضافة **pgvector** المدمجة في قاعدة بيانات PostgreSQL لتكون مخزن المتجهات الأساسي بدلاً من الاعتماد على قواعد بيانات مستقلة ومكلفة مثل Pinecone أو Weaviate.

### أسباب اختيار pgvector للتخزين المتجهي:
- **صفر تكلفة إضافية (Zero Cost Baseline):** تعمل كإضافة داخل نفس خادم قاعدة بيانات Supabase/Neon المجاني.
- **جمع البيانات في استعلام واحد (Single Query Joins):** تسمح لنا بالاستعلام عن المتجهات وربطها (JOIN) بجدول المستندات الأصلي وبيانات الـ Metadata في استعلام SQL واحد متكامل دون الحاجة لإرسال طلبات متعددة عبر الشبكة.
- **توافق كامل مع LangChain:** تدعم LangChain التخزين والاتصال بـ pgvector بشكل أصيل ومستقر وسهل الصيانة.

## 2. Vector Schema & Metadata Design

يتم تخزين المتجهات والبيانات الوصفية (Metadata) داخل جدول `Chunk` بالشكل التالي:

| Column Name | Data Type | Constraint | Purpose |
|-------------|-----------|------------|---------|
| `id` | UUID | Primary Key | Unique identifier for the chunk. |
| `document_id` | UUID | Foreign Key | Links to the parent `Document` (on delete cascade). |
| `content_en` | TEXT | Non-nullable | English chunk text content (if source is EN). |
| `content_ar` | TEXT | Non-nullable | Arabic chunk text content (if source is AR). |
| `embedding_en` | **vector(1536)** | Nullable | 1536-dim vector generated by OpenAI for English text. |
| `embedding_ar` | **vector(1536)** | Nullable | 1536-dim vector generated by OpenAI for Arabic text. |
| `chunk_hash` | VARCHAR(64)| Non-nullable | SHA-256 hash of the content to check for changes. |

## 3. Indexing Strategy (HNSW)

أحد أهم قرارات التصميم لضمان استجابة سريعة جداً للمستقبل هو استخدام فهرس **HNSW (Hierarchical Navigable Small World)** بدلاً من فهرس IVF-Flat التقليدي.

### مميزات HNSW في pgvector:
- لا يتطلب الفهرس عملية تدريب مسبقة (No training phase required)، ويمكن بناؤه فوراً عند إدخال البيانات.
- يتميز بدقة استدعاء عالية جداً (High recall) وسرعة استعلامات فائقة مع زيادة حجم البيانات.
- نستخدم معامل مسافة جيب التمام (`vector_cosine_ops`) لحساب الزوايا الدلالية بين المتجهات.

### SQL Index Definitions:
```sql
-- English vector index tuning
CREATE INDEX IF NOT EXISTS "Chunk_embedding_en_hnsw_idx" 
ON "Chunk" USING hnsw (embedding_en vector_cosine_ops) 
WITH (m = 16, ef_construction = 64);

-- Arabic vector index tuning
CREATE INDEX IF NOT EXISTS "Chunk_embedding_ar_hnsw_idx" 
ON "Chunk" USING hnsw (embedding_ar vector_cosine_ops) 
WITH (m = 16, ef_construction = 64);
```
- **m (16):** يحدد الحد الأقصى لروابط الاتصال بكل عنصر في كل طبقة في الرسم البياني (Graph). 16 يمثل توازناً مثالياً لدقة الـ RAG.
- **ef_construction (64):** يحدد مساحة البحث أثناء بناء الفهرس. القيمة 64 تضمن جودة عالية في دقة الاسترجاع دون التسبب في بطء مفرط في فترات بناء الـ Migration.

## 4. Vector Query Patterns (Cosine Similarity & Filtering)

عند إرسال المستخدم لاستعلام RAG، يقوم خادم FastAPI بالاستعلام عن القطع المتجهية ودمجها ببيانات المستندات وترشيحها باللغة ونوع الوثيقة:

```sql
-- SQL Query Template for Bilingual Semantic Search with metadata filtering
SELECT 
  c.id, 
  c.content_en, 
  c.content_ar, 
  d.doc_type, 
  d.source_url,
  (c.embedding_en <=> :query_vector) AS cosine_distance
FROM "Chunk" c
JOIN "Document" d ON c.document_id = d.id
WHERE 
  d.doc_type = :doc_type_filter -- Metadata filter (optional)
  AND c.embedding_en IS NOT NULL
ORDER BY cosine_distance ASC
LIMIT :limit_k;
```
*ملاحظة:* العامل `<=>` يمثل حساب مسافة جيب التمام (Cosine Distance). ترتيب النتائج تصاعدياً (`ASC`) يجلب أقرب المتجهات دلالياً (الزاوية الأقل تعني التشابه الأعلى).

## 5. Maintenance & Re-indexing Strategy

على الرغم من صغر حجم مستودع محتويات الموقع الحالي (~1000 قطعة كحد أقصى)، نضع هذه القواعد للصيانة بعيدة المدى:

1. **إعادة البناء الدورية (Re-indexing on build):**
   - لا تسبب عمليات التحديث البسيطة للمستندات تراجعاً في أداء HNSW. يتم إعادة بناء الفهرس آلياً مع هجرات Prisma فقط عند الحاجة لتعديل أبعاد التضمين.
2. **معامل `ef_search`:**
   - نضبط معامل سرعة البحث للمتصفحات النشطة برمجياً في جلسات الاتصال لزيادة سرعة الرد:
     ```sql
     SET hnsw.ef_search = 16;
     ```
     تخفيض القيمة لـ 16 يزيد من سرعة الاستعلامات بشكل هائل مع تراجع ضئيل غير محسوس في الدقة.
